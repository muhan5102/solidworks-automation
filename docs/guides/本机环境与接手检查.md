案例入口见[运行入口](../../practice/运行入口.md)，当前成果与尚未验证范围见[训练进度](../../practice/训练进度.md)。

新增学习资料的适用范围见[成图秘籍技巧筛选](../reviews/2026-11/2026-11-17-成图秘籍适用技巧筛选.md)。王静配套STP库仅按项目规则第2节在独立完成并保存自检结果后打开对应件；实际路径留在本机未纳管清单，接手时不预览全库。

## 接手顺序

1. 查看`git status --short --branch`，核对当前分支、已有修改、对应案例和新输出目录；不直接执行历史修复脚本。
2. 先运行下面两项离线检查。它们不连接CAD，成功也不代表SolidWorks环境就绪。
3. 核对本机Skill安装位置，运行其入口自检；准备实际CAD操作时再核对会话、PID、版本、可见窗口、已打开文档和未保存状态。
4. 需要`session.json`的案例只写本轮真实进程信息到未纳管输出目录。端口、PID、活动文档和原图路径不从旧日志照搬。
5. 按案例读取特定版本API和阶段条件；执行后依原图核验、保存关闭，并保留恢复点。

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tools/check_repository.py

$solidworksSkill = if ($env:CODEX_HOME) {
    Join-Path $env:CODEX_HOME 'skills/solidworks-automation'
} else {
    Join-Path $env:USERPROFILE '.codex/skills/solidworks-automation'
}
python -X utf8 "$solidworksSkill/scripts/sw_preflight.py" --no-install
```

`--no-install`用于只检查当前环境；按实际诊断处理依赖，不在训练中途无依据地改变环境。
本次入口自检已执行成功；备份恢复副本亦在SW2024 Revision 32.0.1中只读打开、重建并回读单实体与特征健康，随后关闭。
这只验证恢复可用性，不重新宣称原图验收或STEP重导入。原始输出只留在本机维护目录，源模板、资料路径、恢复设置和MCP配置保持本机管理。

## 成果备份与恢复

GitHub保存代码与记录，`outputs/`中的模型、导出和原始证据仍需本机独立快照。
备份放在仓库之外，并核对源与目标所在物理磁盘；日期快照不覆盖上次备份。
快照应同时包含当时维护代码及本机运行产物，以便恢复后解释模型来源。
记录归档成员、SHA-256、完整性检查和实际恢复验证，位置清单与原始报告只留本机。

恢复先解包到新的核对目录并比较哈希，确认依赖完整，再按案例选择代表性原生文件重开。
验证副本使用不同文件基本名，核验后关闭，不覆盖现有成果或自动重新运行建模脚本。
压缩包存在、CRC通过、字节恢复一致及CAD重开是不同层级的证据，结果分别记录。
