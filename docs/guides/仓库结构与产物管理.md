# 仓库结构与产物管理

长期保留的维护代码和知识进入Git，本机模型与原始运行证据留在被忽略的 `outputs/`。
当前状态只在 `practice/训练进度.md` 维护；单题尺寸、耗时、失败与纠错在案例记录中详述，跨题结论放复盘。

| 位置 | 职责 |
|---|---|
| `AGENTS.md` | 项目执行底线与授权边界 |
| `docs/guides/`、`docs/templates/` | 可复用指南和记录模板 |
| `docs/reviews/<年月>/` | 跨案例复盘，保留验证范围 |
| `docs/tooling/` | 工具验证记录；版本相关经验仍优先留在仓库外本机参考 |
| `practice/<来源>/<案例>/` | 维护脚本、题目身份和实践记录 |
| `practice/shared/` | 多案例共用辅助函数，不含题目尺寸或答案 |
| `practice/history/` | 原阶段快照；保持历史身份，不作为现状 |
| `tools/` | 小型仓库维护工具，不承载题目建模 |
| `tests/` | 标准库检查器回归，故障样本拒绝与修复恢复验证 |

本机产物分区：

```text
outputs/
  practice/<来源>/<案例>/<YYYYMMDD-rNN[-用途]>/
  deliverables/<来源>/<案例>/<YYYYMMDD-rNN[-用途]>/
  tooling/<工具或验证主题>/<轮次>/
  preparation/<日期>/<候选筛选或通用准备>/
  contributions/<对象>/<日期>/
  reports/<日期>/<跨案例报告>/
  handoffs/<日期>/
  maintenance/<维护任务>/
```

来源用 `year08`、`wangjing` 等稳定名称，案例沿用现有英文标识；日期与轮次区分首次、修订及重放。
同日同案例有重放或流程对照时用 `-replay`、`-reuse` 等用途后缀。不覆盖首轮结果，不在根目录新增散文件。
暂留题仍归到对应案例输出位置，记录已接触和未完成状态，不能移进交付目录伪装完成。

每轮运行目录保存原生文件、STEP、题面渲染、阶段证据、检查报告及必要失败副本。
历史运行目录整体保留；整理时只更新维护入口，不批量改写其中的日志、配置快照或现场脚本。
现场脚本不作为新的执行入口，确需复用时将已修订代码纳入对应案例，并注明验证状态。
新轮次只在确有实际需要时分 `input/`、`evidence/` 等子目录，不为简单件强行拆层。

`deliverables/` 只放从明确最终版本复制出来的干净成果：原生文件、要求的导出物、必要预览和交付说明。
复制前核对案例的最终状态及文件哈希，复制后比对源文件；说明来源轮次、检查范围和限制。
保留原始运行目录，后续修订使用新的轮次和交付目录，不直接改已发布副本。
单件可按现有 `completion.json` 的文件清单收集；装配、工程图必须连同完整依赖另行核验，不能只复制顶层文件。

本机资料路径、原始日志和配置备份只留在忽略目录；Git文档使用仓库相对路径或环境变量占位。
仓库检查只核对代码、链接和组织结构，模型验收仍按题面、原生几何及实际目视证据进行。
用户明确淘汰的早期项目从当前工作区删除；其余训练的首次失败和修复证据继续保留。Git已有历史不在本轮改写。

2026-11-17迁移的旧新路径对照、3079个原输出文件的SHA-256和规则修改前备份位于
`outputs/maintenance/repo-layout-20261117/`。历史快照或旧交接中的路径先按这份对照定位；
本次迁移不改变历史模型的验收结论。

## 仓库协作与检查

项目改动默认从当前`main`建立`codex/<主题>`工作分支，复用合适的现有分支也可以。
在分支完成相关代码、文档与本地检查，再按本机GitHub通用流程执行隐私扫描和签名提交。
提交前默认留在工作区供用户审核；每次推送单独取得当前对话明确授权，推送后创建以`main`为目标的PR。
PR说明具体问题、最终改动、验证结果和未验证范围；通过检查并经审核后合并，合并操作另按当次授权执行。
已在当前对话明确授权的步骤不重复询问；采用PR方式不等于允许自动合并，也不自动改变远端分支保护设置。
一个PR聚焦一个目标，不夹带无关重排；公共函数签名、默认行为或删除入口影响既有案例时，写清兼容性与撤回办法。
合并前确认分支包含最新`main`，并核对当前PR头提交对应的`Repository checks`实际通过；基线更新后重新检查。
本地结果不能替代GitHub实际运行结果。当前按用户与AI协作自查，不将同一维护流程中的自查表述为独立第三方审核。
检查未运行、失败或未配置为远端必需状态时如实记录，不把工作流文件存在写成已启用强制合并门禁。

本地与CI共用`python -X utf8 tools/check_repository.py`，检查Python语法、公共导入及当前维护文档的相对链接；
`python -X utf8 -m unittest discover -s tests -v`验证检查器确实能拒绝错误、修复后恢复，并且不执行案例脚本。
[Repository checks](../../.github/workflows/repository-check.yml)在推送到`main`、创建/更新PR和手动触发时运行，
使用GitHub托管Linux和Python 3.12，无第三方Python依赖；另检查本次PR或推送范围的Git差异格式，手动触发时检查最新提交。
检查失败先修复相关问题，再更新同一个PR；不要为跳过报错而放宽检查或移动文件到忽略目录。
历史快照与本机输出不属于当前文档链接检查范围。CI通过只表示这些仓库检查通过，CAD几何、参数化、重建及目视仍按案例实际核验。
环境核对、独立磁盘成果快照和恢复方法见[本机环境与接手检查](本机环境与接手检查.md)；备份位置和原始报告不纳入公开仓库。

上述单目标PR、影响范围与证据分级的做法参考[上游贡献指南](https://github.com/wzyn20051216/solidworks-automation-skill/blob/36bc337357723b9763759ff06e4a1afab990b823/CONTRIBUTING.md)，
按本项目的实践用途与单维护者协作方式调整；上游发布构建和远程CAD流程不属于本仓库的CI范围。
