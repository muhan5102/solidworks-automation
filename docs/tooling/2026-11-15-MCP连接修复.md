# 正式MCP连接修复

日期：2026-11-15。范围：修复正式SolidWorks连接器，并验证当前聊天入口；不继续新题建模。

## 已确认的问题与改动

SW2024 SP0.1正常运行，直接API可以连接，但正式MCP经运行对象表调用`GetActiveObject`失败，连接器只等待并返回`SW_INSTANCE_NOT_READY`。先前隔离修复没有进入正式代码，长驻服务也不会因磁盘文件变更自动替换已导入的模块。

正式`solidworks-automation/scripts/sw_connect.py`现已加入有身份核对的连接回退：

1. 仍先尝试原有运行对象表连接。
2. 已有实例不可通过该入口取得时，只对版本已知、目标唯一的实例使用版本化`Dispatch`。
3. 验证返回PID、实际版本和前后进程清单；身份不明、多目标、PID/版本不符或进程清单变化时拒绝继续。
4. 附着成功仍标记为既有实例，不取得退出用户实例的所有权。

没有更改正式MCP的命令、脚本路径、孔特征封装或其他建模工具。配置曾临时切换`enabled`以探测重载，但未触发旧服务更新，随后已逐字节恢复原配置。用户重启后配置中出现显式`enabled = true`（原来省略、默认启用）；此用户/应用变更已保留，正式命令和脚本路径相同，当前工具已生效。

底层为何没有从运行对象表取得SW实例尚未查明；本次修复的是连接器缺少经身份核验的替代连接路径，不声称已修复Windows的COM注册机制。
